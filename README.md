# Голосовой ассистент

Локальный русскоязычный ассистент: слушает микрофон, отвечает голосом, ставит таймеры и напоминания, управляет музыкой и громкостью, смотрит погоду и сайты, запоминает факты о тебе и **сценарии** — один раз объяснил, где смотреть расписание, дальше он ходит туда сам.

```
микрофон → Silero VAD → GigaAM v3 → Qwen3-4B (LM Studio) ⇄ инструменты
                                          │ проверенный ответ
                                          ▼
                              Silero v5.5 (или Edge TTS) → колонки
```

## Запуск

Доступны два профиля: Нора и мужской Джарвиз. Общие инструменты и обработка звука одинаковые; имя, характер, голос и база памяти выбираются профилем.

```bash
uv run --extra barge-in python -m voice_assistant --profile jarvis
uv run --extra barge-in python -m voice_assistant --profile nora
```

Джарвиз говорит спокойнее и сдержаннее, о себе — в мужском роде. Голос по умолчанию — встроенный мужской Silero `eugene` (это не копия голоса актёра из фильма). Обращение «Джарвиз», «Джарвис» или `Jarvis` работает в начале, середине и конце реплики. Готовые ответы тоже мужские: «поставил», «запомнил», «отменил». Память и таймеры Джарвиза находятся в `data/jarvis/assistant.db`, Норы — в прежней `data/assistant.db`; журналы агента также разделены. Одновременно запускается один профиль, чтобы ассистенты не слышали друг друга.

`--profile` выбирает профиль на один запуск; `ASSISTANT_PROFILE=jarvis` в `.env` — по умолчанию. Настройки Джарвиза: `JARVIS_WAKE_WORD`, `JARVIS_SILERO_SPEAKER`, `JARVIS_EDGE_TTS_VOICE`, `JARVIS_DB_PATH`. Значения `WAKE_WORD` и `SILERO_SPEAKER` Норы не переопределяют мужской профиль. Текстовый тест: `uv run python -m voice_assistant --profile jarvis --text --mute`.

1. LM Studio: загрузить `qwen3-4b-instruct-2507` (контекст 8192) и включить сервер на `localhost:1234`.
2. Зависимости и первый запуск (модель GigaAM, ~160 МБ, скачается сама):

```bash
cd ~/Projects/assistent/app
uv sync
cp .env.example .env              # при желании поправить
uv run python -m voice_assistant  # голосом
```

Другие режимы:

```bash
uv run python -m voice_assistant --text            # печатать вместо голоса (/new — новый разговор)
uv run python -m voice_assistant --text --mute     # и без озвучки
uv run python -m voice_assistant --once "Какая погода завтра?"
uv run python -m voice_assistant --wav запись.wav  # запись вместо микрофона (проверка без микрофона)
uv run python -m voice_assistant --tts silero      # только локальный голос
uv run pytest                                       # тесты
```

Если ассистент ничего не слышит, проверь, не выключен ли микрофон: `wpctl get-volume @DEFAULT_AUDIO_SOURCE@` (включить: `wpctl set-mute @DEFAULT_AUDIO_SOURCE@ 0`).

Если `pactl` выдаёт `Connection refused`, проверь `systemctl --user status pipewire pipewire-pulse wireplumber`. Когда работает пользовательская шина, остановленные службы запускаются командой `systemctl --user start pipewire pipewire-pulse wireplumber`. Если недоступна и шина (`Failed to connect to user scope bus`), сначала нужно восстановить пользовательский менеджер systemd или заново войти в графический сеанс; одна смена микрофона не восстанавливает аудиосервер. После OOM это может требовать администратора. Резервный захват PortAudio сначала проверяет 16 кГц, при отказе использует штатную частоту микрофона и непрерывно преобразует звук в 16 кГц.

### Обращение по имени

Каждая фраза распознаётся (GigaAM быстрый). Точное имя работает в любой части реплики: «поставь, Нора, таймер на минуту». Варианты имени с ошибкой распознавания принимаются на краях фразы, чтобы «видел нору лисы» не вызывало ассистента. Одно «Нора» — сигнал, дальше можно говорить просьбу. После ответа 15 секунд слушает без имени. В тихом режиме продолжение без имени отключено.

Сегмент VAD ещё не означает готовую просьбу: соседние фразы собираются до общей паузы `TURN_PAUSE_S=2.4`. После незавершённых «я хочу», «чтобы», «поставь таймер» ожидание увеличивается до `TURN_INCOMPLETE_PAUSE_S=4.5`. Это простые правила, а не модель понимания завершённости. Микрофон продолжает собирать речь во время STT. `VAD_MIN_SILENCE_MS` задаёт разбиение аудио, а не момент выполнения команды. Отключить имя: `WAKE_WORD=` в `.env`.

Короткие команды таймера («поставь таймер на пять минут», «сколько осталось до таймера», «отмени таймер»), пауза/переключение треков и изменение громкости выполняются напрямую, без LLM. Если сказано только «поставь таймер», Нора спросит длительность. Составные просьбы обрабатывает модель.

### Перебивание

Пока Нора думает или говорит, микрофон не выключается: сегменты ограничены 1,2 с, услышанное распознаётся, и слова собственной озвучки отбрасываются (колонки ноутбука она тоже слышит). Это ограничение длины сегмента, а не гарантия времени реакции. Имя или «стоп / хватит / подожди» обрывают ответ; «помолчи» также включает тихий режим. Новая просьба после имени сначала собирается до конца паузы. Отключить: `BARGE_IN=0`.

Дополнительный потоковый канал Vosk обнаруживает имя и остановку ещё до завершения сегмента. Полный запрос по-прежнему распознаёт GigaAM. `BARGE_ENGINE=auto` использует Vosk, только если пакет и модель уже установлены; иначе остаётся прежний путь. `BARGE_ENGINE=gigaam` отключает дополнительный канал, `BARGE_ENGINE=vosk` требует его наличия. Автоматической загрузки при запуске нет:

```bash
uv sync --extra barge-in
uv run python -m voice_assistant.barge --download-model
```

Воспроизводимое сравнение на синтетических голосах: `uv run --extra barge-in python scripts/benchmark_barge.py /tmp/nora-barge-benchmark.json`. Оно проверяет команды и фоновые фразы, но не заменяет проверку живого голоса и акустики комнаты.

### Эхоподавление и музыка

`AEC_MODE=auto` создаёт временный WebRTC-фильтр PipeWire/PulseAudio. Микрофон читается через `parec`, голос выводится через `pacat` в тот же фильтр как опорный сигнал. Это акустическая обработка до VAD и STT; текстовое сравнение собственной озвучки остаётся дополнительной защитой. Нужны `pactl`, `parec`, `pacat` и поддержка `module-echo-cancel` с WebRTC. [Описание PipeWire](https://docs.pipewire.org/page_pulse_module_echo_cancel.html).

Системные устройства по умолчанию приложение не переключает. Созданный модуль выгружается при нормальном выходе и обработанных ошибках. `AEC_MODE=on` требует AEC и останавливает запуск при ошибке; `off` отключает. В `auto` недоступный фильтр даёт предупреждение и обычный микрофон. Для конкретных физических устройств используй `AEC_SOURCE`/`AEC_SINK` с именами из `pactl list short sources/sinks`; явные PortAudio-устройства `AUDIO_INPUT_DEVICE`/`AUDIO_OUTPUT_DEVICE` отключают автоматическую маршрутизацию. Файлы WAV и текстовый режим обходят AEC.

`MUSIC_DUCK=1` понижает громкость играющих MPRIS-плееров до `MUSIC_DUCK_FACTOR=0.35` на время разговора, затем восстанавливает её. Системная громкость не меняется, остановленная музыка не запускается. Ручное изменение громкости плеера во время разговора сохраняется. Плеер должен поддерживать громкость через MPRIS. При аварийном завершении процесса (SIGKILL) очистка и восстановление не гарантируются.

### Память о пользователе

Явные команды обрабатываются кодом без LLM, с подтверждением только после записи в SQLite:

- «Запомни, что я пью кофе без сахара» — сохранить; повтор той же записи не создаёт дубль.
- «Что ты обо мне помнишь?» — показать факты и номера.
- «Перезапиши факт номер 3 на я пью чай без сахара» — изменить запись на месте.
- «Забудь про кофе» или «Удали из памяти факт номер 3» — удалить выбранный факт. Если подходят несколько или непонятен объект, ассистент уточнит, ничего не меняя.

«Запомни: моя группа 123» заменяет прежнюю группу, а не добавляет вторую. Это также работает для имени и противоположного предпочтения с тем же предметом («я люблю кофе» / «я не люблю кофе»). Произвольные перефразировки семантически не объединяются: для них используй явную перезапись по номеру.

Самостоятельная память консервативная, без дополнительного запроса к модели: прямое сообщение имени/учебной группы сохраняется сразу, предпочтение вида «я люблю…», «я предпочитаю…», «мне нравится…» — после двух одинаковых по нормализации реплик. О сохранении ассистент сообщает «Запомнил/Запомнила: …». Счётчики повторов сохраняются между запусками; до сохранения факта хранится только хэш и счётчик. Цитаты, вопросы, временные сведения и распознаваемые секреты не сохраняются автоматически. Это набор правил, не универсальное понимание важности или чувствительности любой фразы.

Автопамять не перезаписывает уже сохранённые значения имени/группы и противоположные предпочтения с тем же предметом. При удалении/исправлении старый контекст разговора очищается; хэш удалённого факта запрещает его автоматическое возвращение. По новой явной просьбе факт можно сохранить снова. Это логическое удаление из базы и контекста, не гарантированное стирание из файловых резервных копий или прежних журналов. Факты и повторения разделены по профилям; отключение `remember` отключает и автопамять. Сценарии, таймеры и напоминания эти команды не удаляют.

### Доступные инструменты

Скажи «что ты умеешь» или «список навыков». Включённые группы: `alarms`, `memory`, `web`, `weather`, `media`, `computer`, `coder`, `listening`. `TOOL_GROUPS=all` включает всё; например, `TOOL_GROUPS=alarms,memory,media,listening` оставляет бытовые функции. `DISABLED_TOOLS=type_text,ask_coder` отключает отдельные инструменты. Отключённые команды не исполняются и не выдаются модели.

По явной теме запроса модель получает соответствующие группы и общие инструменты; при неоднозначности — весь включённый набор. Каталог и `enable_skill` позволяют расширить набор в ходе запроса, но не включают отключённые в настройках группы. Использованные в истории инструменты также сохраняются в доступном наборе. Это уменьшает размер схем, но эффект на скорость локальной LLM ещё нужно измерить: смена набора может менять кэш промпта.

Аргументы проверяются по обязательным полям, базовым типам и enum. Асинхронные вызовы ограничены 30 секундами по умолчанию; `@reg.tool(..., timeout_s=...)` задаёт свой срок. Быстрые синхронные обработчики SQLite выполняются в основном потоке. Новый навык — модуль с `register(reg, ctx)`, добавленный в словарь модулей в `build_tools`; описание, параметры и обработчик регистрируются через `@reg.tool`. Произвольный код из интернета автоматически не загружается.

Горячая клавиша «замолчи» для Hyprland:

```
bind = SUPER, Escape, exec, pkill -USR1 -f "python -m voice_assistant"
```

### Индикатор на экране

Внизу по центру поверх окон находится компактная панель с именем помощника. Перетаскивание левой кнопкой перемещает её, правый клик возвращает исходное положение. Координаты сохраняются отдельно для профилей в `data/indicator-position.json` и `data/jarvis/indicator-position.json`. На Hyprland используется положение курсора из IPC; на других композиторах — локальные координаты событий.

| Вид | Значит |
|---|---|
| серая точка | ждёт имени; при любой речи рядом точка светлеет |
| синяя точка с волной, «Слушаю» и полоска | услышала имя или только что ответила: говори без имени, пока не кончилась полоска |
| жёлтое кольцо, «Думаю» | распознала фразу, готовит ответ |
| зелёные столбики, «Говорю» | отвечает; при BARGE_IN=1 микрофон продолжает слушать |
| красная точка, «Микрофон выключен» | микрофон выключен в системе — она ничего не услышит |
| карточка задачи | название, агент, фактический статус и время с момента принятия задачи |

Рисует `overlay.py` через системный Python (GTK3 + gtk-layer-shell). Наверх: `INDICATOR=top`, выключить: `INDICATOR=off`.

Статусы задач: «Жду подтверждения» → «Запускаю» → «Выполняется» → «Проверяю» → «Готово», либо «Ошибка»/«Отменено». «Выполняется» появляется только после создания процесса агента, «Проверяю» — при запуске тестов собственного кода. Видны до трёх задач; завершённые скрываются через 90 секунд. Это состояние текущего сеанса, не восстановление задач после перезапуска.

### Границы возможностей

Промпт перечисляет реально включённые инструменты и запрещает обещать отсутствующие действия. Запрос нового умения с «через Кодекс сейчас себе функцию» и словами-паразитами обрабатывается напрямую, без решения LLM. Изменение кода всё равно требует отдельного «да».

Текст одного ответа модели сначала собирается и проверяется, затем передаётся в озвучку. Текстовая преамбула перед вызовом инструмента не озвучивается; подтверждение берётся из результата инструмента. Если модель обещает запуск агента, таймер или другое проверяемое действие без соответствующего успешного вызова, вместо обещания звучит отказ. Проверка формулировок эвристическая, не универсальная проверка любых утверждений. Полная буферизация может увеличить задержку первого звука; прежние замеры ниже не учитывают её.

### Программист-агент

Запрос на апгрейд собственного кода передаётся как дословные распознанные реплики, а не пересказ локальной модели. Начальная просьба и последующая диктовка идут отдельными цитатами в исходном порядке; слова-паразиты, числа и пунктуация внутри цитат не исправляются. Служебный контекст отделён от слов пользователя, прежнее ограничение «один небольшой инструмент» убрано. Даже при вызове через LLM исходная реплика подставляется кодом вместо её пересказа. Подтверждение «да» не заменяет текст уже подготовленной задачи.

`ask_coder` по умолчанию запускает `codex exec` в папке проекта (`self` — сама Нора, иначе папка в `~/Projects`). Экономные настройки: `CODEX_MODEL=gpt-6-luna`, `CODEX_REASONING_EFFORT=low`; оба параметра можно изменить в `.env`. Claude оставлен только для явных просьб. При ошибке выбранной модели автоматического перехода на более дорогую нет.

- **Вопрос** — только чтение (Claude: Read/Glob/Grep/WebSearch/WebFetch; Codex: `--sandbox read-only`), без подтверждения.
- **Изменение** — только после «да». Claude: `acceptEdits` и белый список (правка файлов, `uv run pytest`, `git status/diff`); Codex: `--sandbox workspace-write`. Для собственного кода перед запуском делается снимок git, после изменения запускаются тесты; при успехе сохраняется коммит. Ошибка тестов означает статус «Ошибка», а не «Готово»; автоматического перезапуска нет. `restart_assistant` перезапускает, только если тесты проходят.
- Журналы — `data/coder/`.

### Как работают сценарии

После ответа, в котором ассистент ходил по сайтам, фоновый запрос к модели решает, объяснил ли ты повторяющуюся задачу. Если да — сохраняются имя, слова-триггеры («расписание, пары, занятия») и **прямой адрес** страницы (только из реально открытых). Когда следующая просьба содержит триггер, код сам открывает эту страницу с вопросом в качестве поиска (`завтра`, `в четверг` превращаются в даты, как их печатает сайт), и модели остаётся только ответить. Сайты, которые рисуются JavaScript, пока не читаются.

## Скорость (Ryzen 7 8845HS, Radeon 780M, без дискретной видеокарты)

Ниже прежние замеры обработки. В голосовом режиме теперь дополнительно учитывается ожидание завершения реплики: общая пауза 2,4 с, для незаконченных фраз 4,5 с. Простые таймеры, музыка и громкость обходят LLM. Новые полные замеры с живым микрофоном ещё не сделаны.

| Этап | Время |
|---|---|
| Распознавание фразы (GigaAM) | ~0.1 с |
| Первое слово LLM, обычный вопрос | 0.8–1.3 с |
| Первый звук, короткий ответ, Silero | ~1.3 с от конца фразы |
| Команда с инструментом (таймер, громкость) | 2–3 с |
| Вопрос по сохранённому сценарию (сайт) | 10–15 с, сразу говорит «Сейчас посмотрю» |

Почему быстро: системный промпт не меняется между запросами (время и таймеры идут в сообщение пользователя), и LM Studio переиспользует посчитанный префикс; после изменения памяти он прогревается в фоне. Простые команды отвечают готовой фразой без второго запроса к модели.

## Устройство

```
voice_assistant/
  __main__.py   вход, режимы, голосовой цикл
  assistant.py  ход разговора: промпт → поток → инструменты → ответ
  routines.py   сценарии: узнавание по триггерам и обучение
  skills.py     «допиши функцию»: уточнение подробностей и задание агенту
  listening.py  «не перебивай»: долгое слушание без имени, ответ после длинной паузы
  prompts.py    системный промпт и контекст хода
  llm.py        потоковый клиент OpenAI-совместимого API
  audio.py      микрофон, Silero VAD, воспроизведение, --wav
  audio_system.py временный AEC и обратимое приглушение музыки
  barge.py      дополнительный потоковый детектор перебивания Vosk
  turns.py      сбор продолжения реплики и ожидание завершения
  stt.py        GigaAM (sherpa-onnx) / faster-whisper
  tts.py        Edge, Silero, переключение
  speech.py     нарезка текста на фразы и очередь озвучки
  scheduler.py  срабатывание таймеров и напоминаний
  memory.py     SQLite: факты, сценарии, таймеры

```
